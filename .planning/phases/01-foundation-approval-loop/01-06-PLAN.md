- workflow_dispatch: manual trigger with optional force input

Jobs:
- generate-digest:
  - runs-on: ubuntu-latest
  - steps:
    1. Checkout code (actions/checkout@v4)
    2. Setup Node.js 24 (actions/setup-node@v4)
    3. Install dependencies (npm ci)
    4. Download state artifact (actions/download-artifact@v6)
       - name: digest-state
       - path: .state
       - continue-on-error: true (first run has no artifact)
    5. Run generate-digest script
       - env: EMAIL_API_KEY, APPROVAL_SECRET, APPROVAL_ENDPOINT_URL, EMAIL_FROM
    6. Upload state artifact (actions/upload-artifact@v6)
       - name: digest-state
       - path: .state/digest.json
       - retention-days: 90

2. Add npm scripts to package.json:
   - "generate-digest": "node --import tsx src/actions/generate-digest.ts"
   - "process-approval": "node --import tsx src/actions/process-approval.ts"

Add tsx to devDependencies for TypeScript execution.

IMPORTANT from RESEARCH.md:
- Use artifact v6 (Node.js 24 compatible)
- Artifacts v4+ are immutable - same name is OK across runs
- Offset cron from top of hour to reduce delays
- Document 60-day disable for public repos in comments

Create the workflow that handles approval/skip events:

1. .github/workflows/handle-approval.yml:

Triggers:
- repository_dispatch:
  - types: [approval-received]

Jobs:
- process-approval:
  - runs-on: ubuntu-latest
  - steps:
    1. Checkout code
    2. Setup Node.js 24
    3. Install dependencies (npm ci)
    4. Download state artifact
    5. Run process-approval script
       - env: pass through client_payload
    6. Upload updated state artifact
       - name: digest-state
       - path: .state/digest.json
       - retention-days: 90

Access payload:
- github.event.client_payload.postId
- github.event.client_payload.action
- github.event.client_payload.jti
- github.event.client_payload.timestamp

2. src/actions/process-approval.ts:

Main function:
- Parse environment/inputs for postId, action, jti
- Load state
- If action is 'skip':
  - Update post status to 'skipped'
  - Log "Digest skipped"
- If action is 'approve':
  - Update post status to 'approved'
  - Log "Digest approved - platform posting will occur in Phase 3+"
  - NOTE: Actual platform posting is Phase 3+, just update status for now
- Mark jti as used (for replay prevention)
- Save state

For Phase 1:
- Just update status, don't actually post anywhere
- Log what would happen for debugging
- Real platform posting comes in Phase 3
