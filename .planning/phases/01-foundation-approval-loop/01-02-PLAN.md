<feature>
  <name>HMAC-SHA256 Token Generation and Verification</name>
  <files>src/tokens/sign.ts, src/tokens/verify.ts, tests/tokens.test.ts</files>
  <behavior>
Token signing:
- signToken(payload, secret) -> "base64url_encoded_payload.base64url_signature"
- generateApprovalToken(postId, action, ttlHours, secret) -> token string
- Token contains: { postId, action, exp (timestamp), jti (UUID) }

Token verification:
- verifyToken(token, secret, usedTokens?) -> VerificationResult
- Returns { valid: true, postId, action, jti } for valid tokens
- Returns { valid: false, reason: 'expired' } for expired tokens
- Returns { valid: false, reason: 'invalid-signature' } for tampered tokens
- Returns { valid: false, reason: 'already-used' } when jti in usedTokens
- Returns { valid: false, reason: 'malformed' } for unparseable tokens

Test cases:
1. generateApprovalToken creates token with all required fields
2. signToken + verifyToken roundtrip succeeds
3. Expired token returns { valid: false, reason: 'expired' }
4. Token with wrong secret returns { valid: false, reason: 'invalid-signature' }
5. Token with modified payload returns { valid: false, reason: 'invalid-signature' }
6. Token with jti in usedTokens returns { valid: false, reason: 'already-used' }
7. Garbage input returns { valid: false, reason: 'malformed' }
8. timingSafeEqual is used (not ===) - verify via code inspection
  </behavior>
  <implementation>
Use Node.js crypto module (no external dependencies):
- createHmac('sha256', secret) for signing
- randomUUID() for jti generation
- timingSafeEqual() for constant-time signature comparison (CRITICAL - prevents timing attacks)
- base64url encoding for URL-safe tokens

Implementation notes from RESEARCH.md:
- Token format: base64url(JSON.stringify(payload)).base64url(hmac_signature)
- ALWAYS use timingSafeEqual - never use === for signature comparison
- Buffers must be same length for timingSafeEqual (catch errors = invalid)
- Store jti in state to prevent replay within expiration window
  </implementation>
</feature>
