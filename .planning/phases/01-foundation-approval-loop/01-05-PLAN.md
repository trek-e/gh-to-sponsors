Create GitHub API integration for the Vercel Function:

1. src/vercel/github.ts:

Functions:
- triggerPosting(postId: string, action: 'approve' | 'skip'): Promise<void>
  - POST to /repos/{owner}/{repo}/dispatches
  - event_type: 'approval-received'
  - client_payload: { postId, action, timestamp }
  - Use fetch (built into Node.js 24)
  - Get owner/repo from env vars: GITHUB_OWNER, GITHUB_REPO
  - Get token from env: GITHUB_TOKEN
  - Headers: Accept, Authorization, X-GitHub-Api-Version (2022-11-28)
  - Throw on non-2xx response

- getArtifactState(): Promise<DigestState>
  - List artifacts with name 'digest-state'
  - Download most recent artifact
  - Extract and parse JSON
  - Return DigestState
  - If no artifact exists, return EMPTY_STATE
  - This is for Vercel Function to check token jti and post status

- updateArtifactState(state: DigestState): Promise<void>
  - NOTE: Vercel cannot upload artifacts directly
  - Instead, include state update in repository_dispatch payload
  - The GitHub Action will update the artifact
  - For now, just document this limitation

Add @octokit/rest to dependencies for cleaner API access.

Environment variables needed:
- GITHUB_TOKEN (PAT with repo scope)
- GITHUB_OWNER
- GITHUB_REPO

Implementation notes from RESEARCH.md:
- Repository dispatch requires repo scope PAT
- Artifacts accessible via API with read permissions
- Download returns zip file containing state JSON

Create the Vercel Function that handles approval link clicks:

1. api/approve/[token]/route.ts:

GET handler:
- Extract token from URL path
- Get APPROVAL_SECRET from env
- Call verifyToken(token, secret)
- Get current state via getArtifactState()
- Check if jti already in usedTokens

Responses:
- Invalid signature: 403 with error page
- Expired: 410 with "link expired" page
- Already used: 200 with status page showing what was posted
- Post already approved: 200 with status page
- Valid approve: triggerPosting(), return success page
- Valid skip: triggerPosting(), return "skipped" page

Pages (HTML responses):
- Use src/vercel/pages.ts for HTML rendering
- Simple, clean design matching email style
- No external CSS/JS (inline everything)
- Mobile-friendly viewport meta tag

2. vercel.json:
- Configure functions directory
- Set Node.js 24.x runtime
- Add rewrites if needed for clean URLs
- Set memory/duration limits if needed

Security considerations from RESEARCH.md:
- timingSafeEqual used in verifyToken (from Plan 02)
- Check jti before triggering dispatch
- Include jti in dispatch payload so Action can update state

Flow:
1. Receive request
2. Verify token
3. Check state (is jti used? is post already handled?)
4. Trigger repository_dispatch
5. Return success page (state update happens in Action)
